# Dual-hypothesis relational likelihood ratio protocol

## 1. Question

Does a frame-only comparison of predicted spatial relations under the two
competing anatomy hypotheses add ranking information beyond raw P2-DENSE for
exact class-7/class-19 swaps?

The hypotheses are:

```text
H7  = component is class 7, Fatty tissue esophagus
H19 = component is class 19, Lymph node
```

The verifier score is oriented toward error:

```text
R-LLR = compatibility(counterpart hypothesis)
        - compatibility(predicted-class hypothesis)
```

## 2. Fold-safe knowledge construction

For each held outer fold, load only
`outer_fold_<fold>_train/anatomy_pair_relations.csv`. GT-derived relations from
the held case and test set are prohibited.

Candidate partners are anatomy classes 1–30 excluding 7 and 19. A partner is
eligible only when, for both H7 and H19:

- pooled `relation_observations >= 20`;
- at least three station rows contain one or more observations.

This threshold was frozen from a support-only audit, before R-LLR outcomes were
computed. It is not selected using error labels or held-case performance.

Station is a latent mixture in the deployable score. Filename station, GT
station, and predicted station are not inputs.

## 3. Hypothesis compatibility

For an observed component and each visible eligible predicted partner:

1. compute normalized minimum boundary distance and touch;
2. for every fold-train station row under a hypothesis, compute distance
   compatibility with its `[q05, q95]` envelope;
3. use an envelope width floor of `2 / frame_diagonal`;
4. smooth touch probability as `(p*n + 1) / (n + 2)`;
5. combine distance and touch by the mean log compatibility;
6. marginalize station rows using `relation_observations` weights;
7. clip compatibility to `[1e-6, 1]` before taking logs.

Partner contribution is shrunk by:

```text
min(n_H7, n_H19) / (min(n_H7, n_H19) + 20)
```

R-LLR is the weighted mean of partner log-compatibility differences. Therefore
frames with many visible partners do not automatically receive larger scores.

Missing predicted partners are UNKNOWN and contribute exactly zero. Absence is
not negative anatomical evidence.

## 4. Reliability policy

The failed AA-018 binary gate varied from 18.9% to 78.9% across cases. R-LLR v1
therefore does not multiply or zero the score using tool/entropy reliability.
Reliability remains an audit stratum and future abstention signal. No inpainting
or tool removal is allowed.

## 5. Frozen ablations

| ID | Method | Inputs |
|---|---|---|
| R0 | P2-DENSE raw | dense counterpart probability |
| R1 | R-LLR raw | relational likelihood ratio only |
| R2 | learned P2 | matched logistic control |
| R3 | P2 + R-LLR | primary knowledge information-gain test |
| R4 | P2 + shuffled-partner R-LLR | anatomy-identity negative control |
| R5 | P2 + anatomy-presence vector | non-relational context control |
| R6 | P2 + filename-station one-hot | oracle/non-deployable diagnostic |

Shuffled partner identity uses a deterministic fold-specific permutation of
eligible partner labels and never uses error targets.

## 6. Evaluation and gate

- Cohort: frozen 744 CF005 components / 99 swaps.
- Outer evaluation: leave one OOF validation case out.
- Scaling and logistic fitting: four cases only.
- Test split: unopened.
- Primary metric: macro-case AUPRC.
- Secondary: AUROC, Brier, per-case delta, tiny/non-tiny, direction, evidence
  count, tool/reliability, and training-threshold PPV/recall at 5/10/20/30%.

R3 passes only if it beats both R0 and R2 with:

1. macro-case AUPRC delta at least `+0.02`;
2. improvement in at least 4/5 cases;
3. descriptive case-bootstrap lower bound above zero;
4. non-tiny macro-case AUPRC decrease no worse than `−0.01`;
5. minimum-case PPV decrease no worse than `−0.05` at 5% and 10% coverage;
6. R4 and R5 do not reproduce the full gate.

Any pass is exploratory and selection-leaky because CF005 was selected from the
complete OOF aggregate. It cannot authorize correction, ontology loss, or
clinical deployment.
